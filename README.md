# StudentTrack

StudentTrack помогает вести предметы и оценки по семестрам, следить за средним баллом и рассчитывать, какие результаты по оставшимся работам позволят достичь учебной цели. В приложении несколько аккаунтов с JWT-аутентификацией и изоляцией данных.

## Запуск

Понадобятся Docker и Docker Compose. Скопируй .env.example в .env и установи JWT_SECRET_KEY (не менее 32 случайных байт). Сгенерировать значение: `python -c "import secrets; print(secrets.token_hex(32))"`. Не публикуй .env. Выполни команду из каталога проекта.

```bash
docker compose up --build -d
```

Когда `docker compose ps` покажет статус `healthy` для обоих сервисов, можно открывать приложение.

- [Панель успеваемости](http://127.0.0.1:8000/)
- [Интерактивная документация API](http://127.0.0.1:8000/docs)

Сервис `db` запускает PostgreSQL 17 и хранит данные в именованном томе `postgres_data`. Backend ждёт готовности базы, применяет миграции командой `alembic upgrade head`, затем запускает FastAPI. Маршрут `/health` проверяет подключение к базе реальным запросом `SELECT 1`.

Compose использует локальные значения по умолчанию. Чтобы изменить настройки, скопируй `.env.example` в `.env`. Переменные `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` задают параметры базы при инициализации пустого тома. `STUDENTTRACK_PORT` задаёт порт интерфейса на компьютере. `docker compose down` останавливает сервисы с сохранением тома.

## Работа с оценками

1. Зарегистрируй аккаунт, войди и создай первый семестр. У каждого семестра своя шкала и способ усреднения.
2. Добавь учебные предметы и внеси оценки за выполненные работы. Предметы и оценки можно исправлять и удалять. Удаление предмета также удаляет связанные оценки.
3. Укажи для семестра целевой средний балл. Чтобы рассчитать прогноз, задай число оставшихся работ по каждому предмету.

| Шкала | Допустимые оценки | Допустимая цель |
| --- | --- | --- |
| 5 баллов | целые от 1 до 5 | от 1,00 до 5,00 |
| 12 баллов | целые от 1 до 12 | от 1,00 до 12,00 |
| 100 баллов | целые от 0 до 100 | от 0,01 до 100,00 |

Цель можно задавать с точностью до двух десятичных знаков. Изменение шкалы доступно для семестра без оценок и цели. Каждый новый семестр может использовать собственную шкалу.

### Средний балл, прогресс и прогноз

Среднее предмета — среднее арифметическое его оценок. Для предмета без оценок API возвращает `null` и пропускает его при расчёте общего среднего.

- `subject_means` учитывает каждый предмет с одинаковым весом. Предметы с оценками `[5, 5, 5]` и `[3]` дают результат `4,00`.
- `all_grades` учитывает каждую оценку с одинаковым весом. На тех же данных результат равен `4,50`.
- Прогресс равен отношению текущего среднего к цели в процентах, до `100%`. При отсутствии среднего или цели прогресс недоступен. Достижение цели проверяется до округления. Целевой балл служит ориентиром для планирования учёбы.
- Прогноз подбирает минимальную одинаковую целую оценку для всех указанных будущих работ. Предмет без оценок учитывается, если в нём запланирована работа. Ответ показывает достижимость цели, прогнозируемое среднее при минимальной оценке и лучший результат при максимальных оценках.

Например, при цели `4,40` и одной оставшейся работе по предмету с оценкой `[3]` потребуется `5` в режиме `subject_means` или `4` в режиме `all_grades`.

## REST API

| Ресурс | Маршруты |
| --- | --- |
| Профиль | `POST /api/auth/register`, `POST /api/auth/login`, `GET/PATCH/DELETE /api/students/me` |
| Семестры | `GET/POST /api/semesters`, `GET/PATCH/DELETE /api/semesters/{id}` |
| Предметы | `GET /api/subjects?semester_id=…`, `POST /api/subjects`, `GET/PATCH/DELETE /api/subjects/{id}` |
| Оценки | `GET /api/grades?subject_id=…`, `POST /api/grades`, `GET/PATCH/DELETE /api/grades/{id}` |
| Цель | `GET/PUT/DELETE /api/semesters/{id}/scholarship-settings` |
| Расчёты | `GET /api/statistics?semester_id=…`, `GET /api/scholarship/progress?semester_id=…`, `POST /api/scholarship/forecast` |

Для запросов к защищённым маршрутам сначала зарегистрируйся и получи токен через /api/auth/login. В Swagger нажми Authorize и вставь access_token. Токен действует 30 минут.

Запросы возвращают `404` для отсутствующих записей, `409` при конфликте с текущим состоянием и `422` для недопустимых параметров или значений.

## Архитектура

Браузер отправляет запрос через `fetch`. Маршруты FastAPI принимают данные по Pydantic-схемам и получают сессию SQLAlchemy через зависимость. Код работы с базой ограничивает запросы текущим студентом. Отдельный сервис вычисляет статистику и прогноз по загруженным оценкам.

| Каталог или файл | За что отвечает |
| --- | --- |
| `app/main.py`, `app/api/` | Приложение FastAPI, маршруты, зависимости, отдача интерфейса и проверка готовности |
| `app/db.py`, `app/models/` | Движок и сессии SQLAlchemy 2.0, таблицы и связи PostgreSQL |
| `app/schemas/`, `app/crud/` | Схемы Pydantic v2 и операции чтения и изменения данных |
| `app/services/grading.py` | Чистые функции расчётов, которые тестируются без API и PostgreSQL |
| `app/static/` | Интерфейс на HTML, CSS и JavaScript |
| `alembic/` | История изменений схемы PostgreSQL |
| `tests/` | Модульные, интеграционные и smoke-тесты Pytest, проверки JavaScript |

Семестр принадлежит студенту, предмет принадлежит семестру, а оценка принадлежит предмету. Составные внешние ключи связывают оценку с предметом и шкалой соответствующего семестра, поэтому PostgreSQL может проверить её диапазон даже при прямой записи. Стипендиальная цель связана с семестром один к одному. CurrentStudent проверяет JWT и загружает владельца данных.

Все изменения схемы оформляются миграциями Alembic. Чтобы посмотреть текущую ревизию в запущенном контейнере, выполни `docker compose exec backend alembic current`.

## Тестирование

Разработка идёт от теста к реализации. Сначала тест описывает поведение и обнаруживает его отсутствие. После изменения его запускают повторно вместе с остальными тестами. Модульные тесты покрывают расчёты и отдельные компоненты, а интеграционные применяют миграции к PostgreSQL и проверяют HTTP-контракты и ограничения базы.

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q tests/unit
```

Для интеграционных тестов запусти отдельную временную PostgreSQL. Фикстуры создают изолированные схемы и удаляют их после тестов.

```bash
docker run --rm --detach --name studenttrack-test-db \
  -e POSTGRES_USER=studenttrack -e POSTGRES_PASSWORD=test_password \
  -e POSTGRES_DB=studenttrack_test -p 127.0.0.1:55432:5432 postgres:17-bookworm
```

Дождись готовности базы командой `docker exec studenttrack-test-db pg_isready -h 127.0.0.1 -U studenttrack -d studenttrack_test`, затем запусти тесты.

```bash
STUDENTTRACK_TEST_DATABASE_URL=postgresql+psycopg://studenttrack:test_password@127.0.0.1:55432/studenttrack_test \
  python -m pytest -q tests/integration

STUDENTTRACK_SMOKE_URL=http://127.0.0.1:8000 python -m pytest -q tests/smoke
```

Smoke-тестам нужен запущенный Compose-стек. После интеграционных тестов временную базу можно остановить командой `docker stop studenttrack-test-db`.

Проверки разметки и JavaScript запускаются встроенным тестовым раннером Node.js.

```bash
node --test tests/frontend/dashboard.test.mjs
```

## Перенос старого профиля

Миграция 0002 сохраняет старые оценки, но не даёт войти в старый профиль без назначения учётных данных. Администратор локальной базы может выполнить `docker compose exec backend python -m app.services.claim_profile 1 mylogin` (замени 1 на ID старого профиля). Пароль вводится скрыто. Новые аккаунты не получают доступа к старым данным. Сделай резервную копию базы перед миграцией. JWT хранится в sessionStorage браузера; выход удаляет его локально, но уже выданный токен действителен до истечения 30 минут. Для публичного развёртывания нужны HTTPS, rate limiting и более защищённое управление сессиями.
